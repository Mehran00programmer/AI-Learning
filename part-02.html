01

عامل و محیط

Agent (عامل) هر چیزی است که بتوان آن را موجودی دانست که محیط خود را با sensors (حسگرها) درک می‌کند و با actuators (عملگرها) روی آن اثر می‌گذارد.

نوع عاملحسگرهاعملگرها
انسانچشم، گوش و سایر اندام‌هادست، پا، دهان و سایر اندام‌ها
رباتدوربین و فاصله‌سنج مادون قرمزموتورهای مختلف
عامل از طریق حسگرها ادراک می‌کند و از طریق عملگرها بر محیط اثر می‌گذارد

تابع عامل و برنامه عامل

تابع عامل، تاریخچه ادراک‌ها را به کنش‌ها نگاشت می‌کند: f: P* → A. برنامه عامل روی یک معماری فیزیکی اجرا می‌شود و تابع f را پیاده می‌کند.

فرمول

agent = architecture + program

02

عامل عقلانی

هوش مصنوعی را می‌توان مطالعه طراحی عامل‌های عقلانی دانست. عقلانیت به چهار چیز بستگی دارد:

  • Performance measure: معیاری که موفقیت را تعریف می‌کند
  • دانش قبلی عامل از محیط
  • کنش‌هایی که عامل می‌تواند انجام دهد
  • دنباله ادراک‌های عامل تا این لحظه
تعریف عامل عقلانی

برای هر دنباله ادراک ممکن، یک عامل عقلانی باید کنشی را انتخاب کند که با توجه به شواهدِ دنباله ادراک و دانش درونی عامل، انتظار می‌رود معیار عملکرد را بیشینه کند.

سه هدف اصلی هوش مصنوعی

  • هدف علمی: فهم اصولی که رفتار هوشمند را ممکن می‌کنند
  • هدف مهندسی: ارائه روش‌هایی برای ساخت مصنوعات هوشمند مفید
  • هدف روان‌شناختی: مدل‌سازی انسان (علوم شناختی؛ خارج از این درس)
03

توصیف محیط با PEAS

برای توصیف یک مسئله عامل، چهار جزء PEAS را مشخص می‌کنیم:

حرفمعنیتوضیح
PPerformance Measureمعیار موفقیت
EEnvironmentمحیطی که عامل در آن کار می‌کند
AActuatorsسازوکارهای اثرگذاری بر محیط
SSensorsکانال‌های درک محیط

دنیای جاروبرقی

  • ادراک: مکان و وضعیت محیط، مثل [A, Dirty] یا [B, Clean]
  • کنش‌ها: Left، Right، Suck، NoOp

موفقیت را می‌توان به شکل‌های مختلف تعریف کرد: مقدار گردوغبار تمیزشده، زمان صرف‌شده، برق مصرفی، میزان سروصدا و ...

04

خودمختاری

عاملی خودمختار (autonomous) است که رفتارش را ادراک‌ها و تجربه خودش (با توانایی یادگیری و سازگاری) تعیین کند، نه فقط دانش درونی که از ابتدا در آن قرار داده شده. مثال: جاروبرقی‌ای که یاد می‌گیرد کجا و چه زمانی گردوغبار جدید ظاهر می‌شود.

مثال دیگر SurfBot است: عاملی در محیط وب که پرسش سطح‌بالا (و حتی غیررسمی) را می‌گیرد، اطلاعات مرتبط را پیدا می‌کند و به شکل معنادار ارائه می‌دهد.

06

برنامه عامل

ساده‌ترین قالب برنامه عامل، یک حافظه نگه می‌دارد، آن را با ادراک جدید به‌روز می‌کند، بهترین کنش را انتخاب می‌کند و دوباره حافظه را با کنش به‌روز می‌کند:

Pseudocode — Skeleton Agent 
function SkeletonAgent(percept) returns action
    static: memory      // agent's memory of the world

    memory <- UpdateMemory(memory, percept)
    action <- ChooseBestAction(memory)
    memory <- UpdateMemory(memory, action)
    return action

و یک عامل بازتابی ساده برای دنیای جاروبرقی:

Pseudocode — Reflex Vacuum Agent 
function ReflexVacuumAgent([location, status]) returns action
    if status = Dirty then return Suck
    else if location = A then return Right
    else if location = B then return Left
07

انواع عامل

  1. Table-driven کنش را با جست‌وجو در جدولی برای کل تاریخچه ادراک‌ها پیدا می‌کند؛ جدول بسیار بزرگ می‌شود.
  2. Simple reflex کنش فقط از ادراک فعلی تعیین می‌شود (قانون شرط-کنش). بدون حافظه است و در محیط جزئی‌مشاهده‌پذیر شکست می‌خورد.
  3. Model-based reflex حالت درونی دارد و مدل می‌کند دنیا چگونه تغییر می‌کند و کنش‌ها چه اثری دارند؛ با اطلاعات ناقص هم کار می‌کند، اما بدون هدف مشخص معلوم نیست چه کند.
  4. Goal-based کنش را بر اساس رسیدن به یک هدف انتخاب می‌کند و از برنامه‌ریزی استفاده می‌کند.
  5. Utility-based چند راه‌حل می‌توانند به هدف برسند ولی برخی بهترند؛ utility function مشخص می‌کند کدام بهتر است و بین اهداف رقیب مصالحه می‌کند. مثال: مدیریت سبد سرمایه‌گذاری.
  6. Learning با نظارت بر عملکرد خود و پیشنهاد مدل‌ها و قانون‌های بهتر، در طول زمان بهتر می‌شود؛ بین exploration و exploitation تعادل برقرار می‌کند.
08

مقایسه انواع عامل

سیستم‌های چندعاملی (MAS)

چند عامل در یک محیط مشترک برای اهداف فردی یا جمعی با هم تعامل می‌کنند. انواع: همکارانه، رقابتی و ترکیبی. ویژگی‌ها: خودمختاری هر عامل، ارتباط و هماهنگی، حل مسئله توزیع‌شده و نبود کنترل مرکزی.

عامل‌های سلسله‌مراتبی

رفتار در لایه‌های راهبردی، تاکتیکی و عملیاتی ساخته می‌شود. سطح بالا هدف می‌دهد و سطح پایین آن را به کارهای کوچک‌تر تبدیل می‌کند. مثال: سیستم‌های تحویل با پهپاد.

Utility-Basedتوازن بین چند عامل برای بهترین نتیجهنیازمند تابع مطلوبیت پیچیدهمدیریت سبد سرمایه
