01

بازی‌ها و تنظیمات مسئله

بازی‌هایی مثل شطرنج و گو محیط‌های فشرده‌ای هستند که عدم قطعیت تعامل با دنیای واقعی را شبیه‌سازی می‌کنند. تنظیم مورد بحث: بازی دونفره، نوبتی، قطعی، کاملاً مشاهده‌پذیر، zero-sum و دارای محدودیت زمانی.

  • بازیکن MAX شروع می‌کند و MIN رقیب اوست؛ کنش‌ها به‌نوبت انجام می‌شوند
  • تابع جانشین کنش‌های مجاز و حالت‌های نتیجه را می‌دهد
  • آزمون پایان (terminal test) مشخص می‌کند بازی تمام شده و برد MAX، باخت یا مساوی است

عدم قطعیت اینجا از کنش‌های رقیب می‌آید و هیچ برنامه‌ای موفقیت MAX را در برابر هر پاسخ MIN تضمین نمی‌کند. فضای حالت بزرگ است؛ مثلاً در شطرنج حدود ۱۰⁴⁰ حالت، ضریب انشعاب ≈ ۳۵ و حدود ۱۰۰ حرکت در هر بازی.

02

انتخاب کنش و تابع ارزیابی

  1. ۱ با حالت فعلی، درخت بازی را تا عمق حداکثر ممکن h (افق، horizon) در زمان مجاز بساز.
  2. ۲ حالت‌های برگ را با تابع ارزیابی بسنج.
  3. ۳ مقادیر را از برگ‌ها به ریشه پس‌انتشار کن و بهترین کنش را با فرض بدترین پاسخ MIN انتخاب کن.

تابع ارزیابی e(s) تخمینی هیوریستیک از مطلوب بودن s برای MAX است: e>0 یعنی به نفع MAX، e<0 به نفع MIN و e=0 خنثی. معمولاً مجموع وزن‌دار ویژگی‌هاست: e(s) = Σ wᵢ·fᵢ(s) (مثلاً تعداد مهره‌ها، تعداد حرکت‌ها، خانه‌های تحت کنترل).

مثال دوز

e(s) = تعداد سطر/ستون/قطرهای باز برای MAX منهای تعداد آن‌ها برای MIN.

03

الگوریتم Minimax

گره MAX بیشینه ارزش فرزندانش و گره MIN کمینه ارزش فرزندانش را می‌گیرد؛ در ریشه حرکتی انتخاب می‌شود که به فرزند MIN با بزرگ‌ترین مقدار پس‌انتشاریافته می‌رسد.

Pseudocode — Minimax 
function MINIMAX(s, depth, isMax)
    if TERMINAL(s) or depth = 0 then return e(s)
    if isMax then return max over s' in SUCC(s) of MINIMAX(s', depth-1, false)
    else         return min over s' in SUCC(s) of MINIMAX(s', depth-1, true)
چرا مقدار پس‌انتشاریافته؟

اگر e قابل اعتماد باشد، مقدار پس‌انتشاریافته تخمین بهتری از ارزش حالت است، چون فرض می‌کند MIN هم خوب بازی می‌کند. در هر نوبت فقط یک حرکت انتخاب می‌شود و این روند تکرار می‌شود.

04

هرس آلفا-بتا

درخت را عمق‌اول تا عمق h کاوش می‌کنیم و شاخه‌هایی را که نمی‌توانند تصمیم نهایی را تغییر دهند هرس می‌کنیم.

  • مقدار β یک گره MIN کران بالا برای مقدار نهایی آن است (هرگز زیاد نمی‌شود)
  • مقدار α یک گره MAX کران پایین برای مقدار نهایی آن است (هرگز کم نمی‌شود)
قواعد قطع

جستجو زیر گره MAX وقتی قطع می‌شود که α آن ≥ β یکی از اجدادِ MIN باشد؛ زیر گره MIN وقتی که β آن ≤ α یکی از اجدادِ MAX باشد.

Pseudocode — Alpha-Beta 
function AB(s, depth, alpha, beta, isMax)
    if TERMINAL(s) or depth = 0 then return e(s)
    for each child c of s:
        v <- AB(c, depth-1, alpha, beta, not isMax)
        if isMax then alpha <- max(alpha, v) else beta <- min(beta, v)
        if alpha >= beta then break      // prune
    return alpha if isMax else beta
05

کارایی هرس و بهبودها

حالتتعداد گره بررسی‌شده
MinimaxO(b^h)
آلفا-بتا در بدترین حالتO(b^h)
ترتیب‌دهی کامل (فرزندان MAX به‌ترتیب نزولی و فرزندان MIN صعودی)O(b^{h/2}) [Knuth & Moore]
ترتیب تصادفی (میانگین)≈ O(b^{3h/4})

ترتیب کامل به یک اوراکل نیاز دارد، پس در عمل فرزندان را بر اساس مقادیر دور قبلی (iterative deepening) مرتب می‌کنند. بهبودهای دیگر: افق تطبیقی، extended search برای مقابله با horizon effect، singular extension، transposition table برای حالت‌های تکراری و null-move search.

07

بازی‌های شانسی

در بازی‌هایی با عنصر شانس (مثل تخته‌نرد) گره‌های chance اضافه می‌شوند و مقدارشان میانگین وزن‌دار فرزندان است:

Expectiminimax

v(n) = Σ P(child)·Minimax(child)؛ مثلاً 0.5×3 + 0.5×4 .... برای بازی‌های چندنفره، بازی‌های با حالت‌های جزئی‌مشاهده‌پذیر (ورق) از جستجو در فضای باور استفاده می‌شود. گره‌ها بیشتر می‌شوند و جستجو سخت‌تر.
